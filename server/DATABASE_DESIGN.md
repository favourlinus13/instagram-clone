# Database Design

## Overview

Our Instagram Clone uses MongoDB as the database. The application is organized into four main collections:

- User
- Post
- Comment
- Notification

Each collection stores a specific type of data and is connected to other collections through references (ObjectIds).

---

# 1. User Collection

## Purpose

The User collection stores information about every registered user. It is responsible for authentication, user profiles, following relationships, and saved posts.

## Fields

| Field          | Purpose                                                      |
| -------------- | ------------------------------------------------------------ |
| \_id           | Unique identifier generated by MongoDB                       |
| username       | Unique username displayed throughout the application         |
| email          | User's email address used for login                          |
| password       | Hashed password for secure authentication                    |
| bio            | Short description displayed on the user's profile            |
| profilePicture | URL of the user's profile image                              |
| followers      | Array of User IDs representing users who follow this account |
| following      | Array of User IDs representing users this account follows    |
| savedPosts     | Array of Post IDs representing bookmarked posts              |
| createdAt      | Date the account was created                                 |
| updatedAt      | Date the account was last updated                            |

## Relationships

- One User can create many Posts.
- One User can write many Comments.
- One User can follow many Users.
- One User can receive many Notifications.

---

# 2. Post Collection

## Purpose

The Post collection stores every image uploaded by users along with captions and engagement data.

## Fields

| Field         | Purpose                                                 |
| ------------- | ------------------------------------------------------- |
| \_id          | Unique identifier generated by MongoDB                  |
| author        | Reference to the User who created the post              |
| image         | URL of the uploaded image                               |
| caption       | Description written by the user                         |
| likes         | Array of User IDs representing users who liked the post |
| commentsCount | Total number of comments on the post                    |
| createdAt     | Date the post was created                               |
| updatedAt     | Date the post was last updated                          |

## Relationships

- Each Post belongs to one User.
- One Post can have many Comments.
- One Post can be liked by many Users.

---

# 3. Comment Collection

## Purpose

The Comment collection stores comments made by users on posts.

## Fields

| Field     | Purpose                                     |
| --------- | ------------------------------------------- |
| \_id      | Unique identifier generated by MongoDB      |
| post      | Reference to the Post being commented on    |
| author    | Reference to the User who wrote the comment |
| text      | The comment content                         |
| createdAt | Date the comment was created                |

## Relationships

- Each Comment belongs to one Post.
- Each Comment belongs to one User.

---

# 4. Notification Collection

## Purpose

The Notification collection stores activity notifications such as likes, comments, and new followers.

## Fields

| Field     | Purpose                                            |
| --------- | -------------------------------------------------- |
| \_id      | Unique identifier generated by MongoDB             |
| recipient | User who receives the notification                 |
| sender    | User who performed the action                      |
| type      | Type of notification (like, comment, follow)       |
| post      | Reference to the related Post (if applicable)      |
| isRead    | Indicates whether the notification has been viewed |
| createdAt | Date the notification was created                  |

## Relationships

- Each Notification belongs to one recipient User.
- Each Notification is triggered by one sender User.
- A Notification may reference one Post.

---

# Collection Relationships

User

- Creates many Posts
- Writes many Comments
- Follows many Users
- Receives many Notifications

Post

- Belongs to one User
- Has many Comments
- Can be liked by many Users

Comment

- Belongs to one User
- Belongs to one Post

Notification

- Belongs to one recipient User
- Created by one sender User
- May reference one Post

---

# Database Design Notes

- Passwords will never be stored as plain text. They will be hashed using bcrypt before being saved.
- Images will not be stored directly in MongoDB. Instead, image URLs from Cloudinary will be stored.
- Relationships between collections will use MongoDB ObjectId references.
- Timestamps (createdAt and updatedAt) will help track when documents are created and modified.
- Arrays such as followers, following, likes, and savedPosts allow us to efficiently model common Instagram features for this project.
